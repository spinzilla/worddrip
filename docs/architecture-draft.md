# 技术方案 v1（2026-11-03 已拍板）

## 一句话

**以 LinguaClip 的源码为底座（Tauri 2 + React），把速查页和 Hermes 学习规则做成新模块装进去**；同一套代码打包出 Windows 安装包和安卓 APK。

为什么选 LinguaClip 当底座：它已经是 Tauri 2 + React，而 Tauri 2 正好能出 Windows 和安卓两个版本；另外两个来源（一个是 HTML 页面，一个是提示词+Markdown）都很容易搬进 React，反过来就难。

## 模块划分

| 模块 | 来源 | 内容 | 安卓端 |
|---|---|---|---|
| 精听 | LinguaClip | 视频/音频导入、字幕、逐句听写 | 听写可用；**本地 whisper 转写先只做 Windows**，安卓用已有字幕或电脑端转好的 |
| 词库 / 复习 | 速查页 | 学术升级库浏览搜索、每日推荐、到期复习、沉浸闪卡、评论楼 | 全功能（主力场景：碎片时间刷词） |
| 教练（AI） | Hermes english-learning | 作文批改、词汇练习出题与 L1–L4 晋级、听力复检、错误档案 | 全功能（拍照手写作文 → vision 批改） |
| 共享数据层 | 新建 | 词条、复习状态、错误档案、听写记录、评论 | 与电脑端同步 |

三个模块互通（这就是「融合」而不是三个并排的软件）：
- 精听里听错的词 → 一键进词库待学
- 词库里的词 → 教练出题、作文批改时检查有没有用上
- 教练批改出的错误 → 写入错误档案 → 词库「易错点」标签自动出现

## 数据与同步

- 本地存储：SQLite（Tauri 官方 SQL 插件），两端相同表结构。
- 初次导入：一次性脚本把 `D:\Hermes\english\` 的 Markdown 词库/错误档案解析进 SQLite；提供「导出回 Markdown」，Hermes 那边照样能用。
- 双端同步（默认方案）：扩展已有腾讯云 FastAPI 后端（已有鉴权、评论、AI 配额），加一组同步接口。备选：Syncthing 同步 SQLite 文件（简单但冲突难处理，不推荐）。

## 「多 agent 协作」分两层

1. **开发层**（本工作区已就位）：`AGENTS.md` 统一规则 + `docs/tasks/` 任务卡认领 + 实现者 ≠ 验收者；Claude Code 子 agent 定义在 `.claude/agents/`；Codex/Hermes 读同一份 AGENTS.md 即可接手。
2. **应用层**（客户端功能）：教练模块内部拆成几个 AI 角色——
   - 分流员：判断用户这次要干什么（对应 SKILL.md 〇）
   - 批改员：作文逐句改错（A）
   - 词汇教练：出题、判 L 级晋级（B）
   - 听力教练：复检、收割生词（D）
   - 档案员：只负责按规则追加归档（C），其他角色不直接写档案

   角色之间通过共享数据层交换结果，而不是互相聊天，省 token、可追溯。模型调用走用户自己的 API key（DeepSeek / 火山方舟等，OpenAI 兼容接口），key 存在本机，不进仓库。

## 主要风险

- **AGPL-3.0**：用了 LinguaClip 的代码，整个客户端都得按 AGPL；自己用完全没问题，若将来公开发布则必须开源全部代码。
- **安卓 + whisper**：手机上跑 whisper 又慢又费电，第一版不做。
- **工具链**：本机目前没有 Rust；安卓打包还需要 Android Studio（SDK + NDK，几个 GB，大陆网络要找镜像）。
- **上手难度**：Rust/React/安卓打包对用户都是新东西，开发主要靠 agent，用户负责拍板和真机验收。

## 开发顺序调整（2026-11-09 用户确认）

**为什么调整**：软件现在能导入、浏览、筛选到期词、翻面和导出，但还不能记录复习结果，也没有手写入口，日常学习仍在 Markdown 上。先补这两处，软件才能成为唯一入口。

**什么时候开始**：用户 2026-11-09 改为立即开始，由 Claude 托管派活。任务卡 022–027 和 019–021 按顺序执行，不做安卓、同步、推送和服务器改动。

| 顺序 | 阶段 | 做什么 | 做到什么算完成 |

## 随手记、安卓和同步（2026-11-11 用户确认）

**随手记**：按草图做，先做电脑端。

- 电脑端：任何页面按 Ctrl+J 在右下角弹一个小输入框，回车就存。自动带上「当时在看什么」：看视频或听写时带当前字幕句和时间点，在词库里带当前词条。
- 整理：词库页新增「随手记」分页，每条一键送去：加入词库（走 042 的手动加词）、存为例句（走 043 的我的例句）、留作笔记、问 AI。本地规则给出建议去向，不调模型。首页或导航显示「今天还没整理 N 条」。可以导出 `随手记.md`。
- 手机端：首页一个输入条，加上安卓的「分享到词滴」。等安卓骨架能跑之后再做。

**安卓**：用 Tauri 把同一套代码打成 APK，不另写一个应用。

- 打进去的是电脑版的界面（词库要靠 Rust 的 SQLite），不是 `app/mobile/` 那套从上游继承来的手机网页版。
- 第一步只做骨架：能装到用户自己的手机上（USB 调试），数据只存在手机本地，窄屏能用首页、随手记、闪卡和词库浏览，电脑专用的功能（导入视频、本地转写等）在手机上隐藏。
- 工具链已装在 `D:\android`（JDK 17、SDK 35、NDK 27.3，2026-11-11 装好）；只装了 `aarch64-linux-android` 这一个 Rust 编译目标。

**同步**：走腾讯云现有的 FastAPI 后端（`/opt/vocab-notes`），做双向同步。

- 用户 2026-11-11 选的是双向同步，没选「只同步到 Notion + 备份」的简单方案。
- 初步设计：每行带 `updated_at` 和 `device_id`，按行「后写的赢」；复习记录只追加，两边合并取并集；听力单词和视频先不同步。
