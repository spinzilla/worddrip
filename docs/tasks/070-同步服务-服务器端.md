## 目标（一两句话，用户能看懂）

写好放在服务器上的「同步服务」：每个用户有自己独立的同步空间，别人碰不到；同一空间里的手机和电脑各自把改过的数据推上来、把对方改过的拉下去，冲突按「后改的为准」处理，复习记录只增不删。服务器有容量和频率限制，防止被刷。这张卡只在本机写好、测好，不碰服务器。

## 协议（071 照这个对接）

- **应用口令**：除 `/health` 外所有请求带 `X-App-Key: <应用口令>`；服务器从环境变量 `SYNC_APP_KEY` 读，常数时间比较；没配置时一律 503，错了 401。应用口令会编进安装包，只用来挡外部乱请求，不当作保密的东西。
- **同步空间**：
  - `POST /spaces`（只要应用口令）→ `{"space_id": str, "space_secret": str}`。`space_id` 是随机短 id（例如 16 位 base32），`space_secret` 是 32 字节随机数的 urlsafe base64；服务器只存 `sha256(space_secret)`，原文只在这次返回里出现一次。按来源 IP 限制：每 IP 每天最多建 5 个空间，超了 429。空间总数上限由 `SYNC_MAX_SPACES`（默认 100，用户 2026-11-13 定的初期名额）决定，满了返回 403 `{"detail": "同步名额已满"}`；删除空间会空出名额。
  - 空间内的请求都带 `Authorization: Bearer <space_id>.<space_secret>`；空间不存在或密钥不对一律 401（不区分哪个错）。
  - `DELETE /space`（带空间凭证）→ 删除这个空间和它的全部数据，返回 `{"ok": true}`。
  - `GET /space` → `{"rows": n, "bytes": n, "quota_bytes": n, "created_at": 毫秒}`。
- **配额与频率**：每个空间数据总量上限由 `SYNC_SPACE_QUOTA_MB`（默认 50）决定，push 会超就整批拒绝，返回 507 `{"detail": "同步空间已满"}`；每个空间每分钟最多 60 次请求，超了 429。
- `GET /health` → `{"ok": true}`（什么都不要）。
- `POST /push`：`{"device_id": str, "changes": [{"table": str, "id": str, "updated_at": int(毫秒), "deleted": bool, "data": object|null}]}`
  - 只作用于凭证所在的空间；不同空间的同名 `(table, id)` 互不影响。
  - `table` 必须在白名单里（见下）；`id` 是该行在同步里的身份字符串（复合主键由客户端拼好）。
  - 对每条：本空间已有同 `(table, id)` 且 `updated_at` 更大 → 忽略；相等 → `device_id` 字典序大的赢；否则覆盖，并给它分配一个新的递增 `seq`。
  - 「只增不删」表（`review_log`、`review_event`）：同 id 已存在就忽略，不覆盖、不删除。
  - 返回 `{"ok": true, "accepted": n, "ignored": n, "cursor": 本空间当前最大 seq}`。整次 push 在一个事务里，失败全部回滚。
  - 限制：一次最多 2000 条、请求体最多 8MB，超了返回 413。
- `GET /pull?since=<seq>&limit=<n≤1000>` → `{"changes": [{"seq", "table", "id", "updated_at", "deleted", "device_id", "data"}], "cursor": 本页最后 seq, "more": bool}`，只返回本空间，按 seq 升序。
- **同步码**（给 071/072 用，服务器不参与）：客户端把 `space_id` 和 `space_secret` 拼成一串便于抄写复制的同步码（格式由 071 定），第二台设备输入后拆回两部分。
- 表白名单：`review_word`、`upgrade_entry`、`upgrade_example`、`self_check`、`review_definition`、`review_definition_example`、`review_log`、`review_event`、`vocab_note`、`vocab_example`、`example_scene`、`quick_note`、`error_top`、`error_batch`、`error_item`、`error_todo`、`error_essay`、`coach_essay`、`coach_top_progress`。服务器不理解每张表的列，`data` 原样存 JSON（限制单条 `data` ≤ 256KB）。

## 要做成什么样

1. 代码放 `server/sync/`：`app.py`（FastAPI）、`store.py`（SQLite 存储：`spaces(space_id PRIMARY KEY, secret_hash, created_at, bytes)`、`rows(space_id, tbl, id, updated_at, device_id, deleted, data, seq, PRIMARY KEY(space_id,tbl,id))` + `(space_id, seq)` 索引 + `meta`；频率限制用内存计数即可）、`requirements.txt`（锁定与服务器一致的版本：fastapi==0.143.0、pydantic==2.14.1、starlette==1.7.0、uvicorn==0.54.0）、`requirements-dev.txt`（pytest、httpx，锁定版本）。数据库路径从环境变量 `SYNC_DB`（默认 `/opt/worddrip-sync/data/sync.db`）读。SQLite 开 WAL。
2. **每日备份**：每天第一次写入前，用 SQLite 在线备份把数据库复制到同目录 `backups/sync-YYYYMMDD.db`，只保留最近 7 份。
3. **部署材料**（只写不执行）放 `server/sync/deploy/`：
   - `worddrip-sync.service`（systemd：`/opt/worddrip-sync/.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8710`，`EnvironmentFile=/etc/worddrip-sync.env`，用一个非 root 的专用用户 `worddrip` 跑，数据目录只给这个用户写）；
   - `nginx-sync-location.conf`：给 `vocab.uestceee.art` 的 443 server 块加的一段 `location /sync-api/ { proxy_pass http://127.0.0.1:8710/; client_max_body_size 8m; ... }`；
   - `worddrip-sync.env.example`（只有键名 `SYNC_APP_KEY=`、`SYNC_DB=`、`SYNC_SPACE_QUOTA_MB=`、`SYNC_MAX_SPACES=`，没有值）；nginx 段里用 `proxy_set_header X-Real-IP $remote_addr`，服务按它取来源 IP；
   - `README.md`：一步一步的部署命令、怎么生成应用口令（`python3 -c "import secrets;print(secrets.token_urlsafe(32))"`）、怎么验证、**怎么完整回退**（停服务、删 nginx 那段、reload、删目录），每步写清会改服务器上哪个文件。
4. 本机开发环境：在 `server/sync/.venv` 建虚拟环境（用 `python -m venv`，pip 用国内镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`），只装 requirements 和 requirements-dev 里的包；`.gitignore` 加 `server/sync/.venv/`、`__pycache__/`、`server/sync/**/*.db*`。
5. 不往仓库写任何口令、真实域名以外的服务器信息（IP 不写进代码）。
