## 目标（一两句话，用户能看懂）

一条命令打出可以发给用户的正式版：手机是正式签名、体积小很多的安装包，电脑是带安装向导、能被自动更新的安装包，同时生成两个「最新版本说明」文件，之后上传到服务器就能让应用检查更新。

## 从哪看起

- `app/src-tauri/tauri.conf.json`（version、bundle）、`app/package.json`、`app/src-tauri/Cargo.toml`。
- `app/dev/build-android.mjs`（现在 debug 包的打法和绕过的坑，正式包照着做 release 版）。
- `app/src-tauri/gen/android/app/build.gradle.kts`（versionCode/versionName 读法、签名配置要加在这里）。
- Tauri 2 官方文档：NSIS 打包、`bundle.createUpdaterArtifacts`、更新签名环境变量 `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`、更新清单 `latest.json` 格式；安卓 release 签名。

## 要做成什么样

1. **电脑安装包**：Windows 上打 NSIS 安装包（按当前用户安装，不需要管理员；桌面和开始菜单快捷方式名「词滴 WordDrip」；卸载时默认**不删**词库数据），并开启 `createUpdaterArtifacts`，产出安装包和对应的 `.sig`。可以用 `tauri.windows.conf.json` 之类的平台配置，别影响安卓构建。identifier 不变。NSIS 工具由 Tauri 自动下载（用户已同意），放在它默认的位置。
2. **手机正式包**：`build.gradle.kts` 加 release 签名：从 `WORDDRIP_RELEASE_DIR\keystore.properties` 读；文件不存在时（别人的电脑）release 构建明确报错说明缺签名，debug 构建不受影响。打 arm64 release APK（照 `build-android.mjs` 的做法写一个 release 版，或给它加 `--release` 参数），开 R8/资源压缩前先确认不会删掉 Tauri 需要的类（不确定就先不开，报告写明）。
3. **版本号**：只在一个地方改（`tauri.conf.json` 的 version），安卓 versionCode 跟着变大（说明规则，例如 Tauri 的 major*1000000+minor*1000+patch）。写一个 `node app/dev/release.mjs bump <版本>` 同步改 `tauri.conf.json`、`package.json`、`Cargo.toml`（三处一致）。
4. **一条命令出全部产物**：`node app/dev/release.mjs build [--notes "更新说明"]`：
   - 构建电脑安装包和手机正式包（签名口令从文件读，经环境变量传给构建，不打印、不进日志）；
   - 输出到 `D:\tmp\es-release\<版本>\`：
     - `WordDrip_<版本>_x64-setup.exe`（以及 `.sig`）；
     - `worddrip-<版本>.apk`；
     - `latest.json`：Tauri 更新器格式，`platforms.windows-x86_64` 的 `url` 指向 `https://vocab.uestceee.art/worddrip-updates/<版本>/WordDrip_<版本>_x64-setup.exe`，`signature` 是 .sig 内容；
     - `android.json`：`{ version, versionCode, url, sha256, size, notes, pub_date }`，`url` 同样指向服务器上的 apk。
   - 构建前检查：工作区有没提交的改动就停下（`--allow-dirty` 可跳过，仅测试用）；版本号三处不一致就停下。
5. **上传脚本**（只写好，本卡不连服务器）：`node app/dev/release.mjs upload <版本> [--dry-run]`：用 `scp` 传到 `tencent:/var/www/worddrip-updates/<版本>/`，两个清单最后传，并且先传成临时名再 `mv` 成正式名，避免用户读到一半的清单；`--dry-run` 只打印要执行的命令。
6. 文档：`docs/release.md` 写清发版步骤、签名材料在哪、丢了会怎样（手机再也不能覆盖更新，只能卸载重装）、怎么备份。
