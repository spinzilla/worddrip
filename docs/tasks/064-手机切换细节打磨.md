## 目标（一两句话，用户能看懂）

把手机上切换时剩下的几处「顿一下」收掉：四个标签切换都轻轻淡入、页面不往下掉；闪卡背面点单词查词时卡片不再自己翻回正面。

## 要做成什么样

1. **四个标签内容区都淡入**：浏览、按场景找、手写收件箱、随手记切换时用同一种淡入（约 150ms），最好在内容区外层统一做，而不是每个面板各加一遍。
2. **切换时标签行不动**：标签行在屏幕里时，切到更短的面板后标签行仍在原来的屏幕位置（例如切换前给内容区设当前高度作最小高度、切换后再放开，或切换后把标签行滚回原位；用你认为最不抖的办法，报告里写清）。
3. **360 宽标签行**：四个标签在 360 宽下不要 3+1 换行，改成一行横向滑动或收窄内边距放进一行；390 宽保持一行。
4. **闪卡背面点词不翻面**：点到能查词的英文单词时只弹查词卡、不翻面；点背面空白处才翻回正面（手机和电脑都改）。

### 第 1 次返工（2026-11-13，统筹 claude）——已返工，2026-11-13 通过

验收者用真机同款触摸（touchstart→touchend）复现了：切到短面板后，下一次手指按下就放开钉住的高度，页面变短、滚动被夹，标签行掉约 196px，而且这一下点不中标签。问题出在「touchstart / wheel 时放开钉住高度」这个做法：手机上任何一次点按都会先触发 touchstart，等于刚钉住就放开，还在点击过程中改了布局。只改下面两件：

1. **不要在 touchstart / wheel 时放开高度**。改成：每次切换时给内容区设一个 `min-height`，大小正好够让页面在当前 scrollTop 下不被夹（大约「滚动容器可视高度 + 当前 scrollTop − 内容区顶部在页面里的位置」，自己量准），这个 min-height 一直保留到下一次切换时重新算；用户往上滚回顶部也不需要放开。短面板下面留一段空白是可以接受的。点按过程中不能有任何布局变化。
2. **360 宽带角标时标签行多出 5px**：把标签的左右内边距或间距再收一点，让带角标时也正好放进一行（`scrollWidth <= clientWidth`）。
3. 改完重跑验收标准 1、3、4、6；第 3 条必须用触摸事件（`Input.dispatchTouchEvent` touchStart→touchEnd）点标签，连续切「按场景找 → 随手记 → 浏览 → 随手记」，每次都切过去、标签行 top 差值不超过 4px；鼠标点击再测一遍。

### 问题清单（按严重程度）

1. **一般｜本卡｜真机触摸时：切到更短的面板后，下一次触摸会让标签行往下掉一截，并且这一下点不中标签。**（导致验收标准 3 在真机上不成立）
   复现：手机 390×844 → 词库 → 浏览列表很长时把标签行滑到屏幕中间（`top≈455`）→ 触摸点「按场景找」（正常，行不动）→ 再触摸点「随手记」：手指一按下（touchstart）钉住的高度就被放开，页面从 1422 缩到 1001、`scrollTop` 459 被夹到 262，标签行 `top` 454.7 → 651，且「随手记」没切过去，要再点一次（这时行已经在 651 了）。
