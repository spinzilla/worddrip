## 目标（一两句话，用户能看懂）

每个词或短语都能记自己的笔记：在词库详情页里看、加、改、删，一个词可以有多条，每条记着时间和来源。导出时笔记单独成一个文件。

## 从哪看起

- 数据库结构：`app/src-tauri/src/vocab/schema.rs`（现在 `SCHEMA_VERSION = 7`，`migrate()` 负责老库升级），查询在 `query.rs`，导出在 `export.rs`，命令注册看 `vocab/mod.rs` 或 `src-tauri/src/lib.rs`。
- 词库界面：`app/components/vocab/EntryDetail.tsx`（详情页）、`BrowsePanel.tsx`（列表、搜索、筛选）。
- 现有的「备注」（`review_word.note`、升级表的备注列）**不是**本卡的笔记：它是复习程序自动追加的记录（如「旧备注；2026-11-09 首考过」），而且会原样写回 Markdown 表格的一个格子。

## 必须守住

1. **单独存**：新建表（例如 `vocab_note`：id、词的归一化键、正文、来源、创建时间、修改时间）。不往现有 `note`/备注列里写，也不改它们。老库升级不丢任何数据，`SCHEMA_VERSION` 加 1，迁移有测试。
2. **按词挂，不按行号挂**：同一个词（忽略大小写和首尾空白；短语按整段）在复习库和升级库里出现，看到的是同一组笔记；重新导入词库后笔记不丢、不错位。归一化规则写进结束报告。
3. **来源字段**先支持 `词库`、`复习`、`首考`、`闪卡` 四种（041 会用到后三种），本卡界面里只产生 `词库`。
4. **词库详情页**：笔记列表（新的在上，显示日期和来源）、添加、编辑、删除（删除要二次确认）。多行文字正常显示；笔记里的英文能点词查词（复用 034 的 `Lookable`）。
5. **列表**：能筛「有笔记的词」；搜索框能搜到笔记正文。
6. **导出**：导出时在同目录额外写一个 `我的笔记.md`（按词分组，每条带日期和来源），没有笔记就不写；原 Markdown 表格和 CSV 不变。
7. **不发给模型**：出题、判分、批改的请求里都不带笔记（写测试断言）。
8. 只用浅色主题、现有颜色变量；390 CSS 像素宽能用、不横向溢出。
9. 不碰真实数据库和 `D:\english`；不调用真实模型；不装软件、不提交、不推送。

### 表结构、归一化规则、迁移方式

```sql
CREATE TABLE vocab_note (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  word_key TEXT NOT NULL CHECK (length(word_key) > 0),   -- 归一化后的词，按它分组
  word TEXT NOT NULL,                                    -- 记下时的写法（保留大小写），展示用
  body TEXT NOT NULL CHECK (length(trim(body)) > 0),     -- 正文，保留中间换行，去首尾空白，最多 4000 字
  source TEXT NOT NULL CHECK (source IN ('词库','复习','首考','闪卡')),
  created_at TEXT NOT NULL,                              -- UTC RFC3339（毫秒），界面和导出显示成本地时间
  updated_at TEXT NOT NULL
);
CREATE INDEX vocab_note_word ON vocab_note(word_key, created_at);
```

- **不引用** `review_word`/`upgrade_entry` 的 ID（没有外键），所以重新导入、行号变化、换 ID、甚至复习行被删，笔记都还在、还挂在同一个词上。
- **归一化规则**（后端 `notes::note_key`，与前端 `normalizeText` 完全一致，两边用同一张 7 条用例表核对）：去掉 `**` → 弯撇号 ’‘ 换成直撇号 ' → 所有空白（含换行、Tab、全角空格）合成一个空格并去首尾 → 转小写。短语按整段算，例如 `In  the Light\tof` → `in the light of`。复习库的词、升级库的候选词都按这个键取笔记。
- **迁移**：沿用原来的逐版本升级，老库打开时 `version <= 7` 就在一个事务里建表、把 `user_version` 写成 8；不改任何已有表。测试从 v7 库（8 张表都有数据）升级，前后逐行比对一致，原「备注」列不变。

### 我自己拿的主意（不同意可以改）
- **`我的笔记.md` 只跟着「导出复习库」写**（和 037 的来源 CSV 一样），不跟「导出升级库」。原因：两种导出常存到同一个文件夹，都写的话第二次会因为文件已存在而失败。文件里是**全部**笔记，包括升级库候选词的。副作用：只有升级库、没有复习库的人导不出笔记（复习库为空时导出按钮是灰的）。
- 笔记对应的词如果后来从两个库里都消失了，界面上看不到它的笔记，但不会删掉，导出时仍会写进 `我的笔记.md`。
