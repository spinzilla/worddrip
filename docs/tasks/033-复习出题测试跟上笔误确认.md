## 结束报告（实现者填）

- 改了什么：只改 `app/dev/fixtures/vocab/recall/e2e.mjs`（030 的复习真实窗口脚本），没改产品代码。具体：
  1. 第 1 屏提交后不再直接等「已保存」：先等 4 题判分出现，断言 `candit` 被判成 `typo/pending`、笔误按钮里有「就是拼错了，判错」、这时「保存并下一屏」是禁用的。
  2. 截图 `05-screen1-typo-pending.png` 后实际点一次 `[data-testid=recall-typo-reject]`（就是拼错了，判错），断言最终判定变成 `['true','true','false','false']`、逐题文字是「答对 / 答对 / 答错（拼写不同）/ 没作答，按答错计」，再截图 `05b-screen1-typo-rejected.png`，然后才点保存。
  3. 第 1、2 屏保存后的等待从「本屏 N 题都保存」（`recall-saved`）改成「判分结果 N 条 + 保存按钮可点」；因为 031 之后提交只判分、点保存才写库，保存时同时切屏，原来的 `recall-saved` 元素会被卸载。
  4. 第 2 屏 allocate 的断言从 `/原形 allocate/` 改成 `/词形不对：这句需要 allocated，不是 allocate/`（031 改了判分原因文案）。
  5. 新增两条防止回退的断言：提交后、点保存前 `review_log` 为 0 行；整轮结束后 `review_event` 为 0 行（拒绝笔误、没标题目出错），证据 JSON 里也记了 `reviewEvents` 和 `kinds1`。
  6. 脚本头注释补上笔误这一步。
- 代码审阅：自查。与 031 的 `RecallReview.tsx` 对照：提交只 `evaluateAnswer` 不写库；笔误题 `correct` 为 null 时保存按钮禁用；点「判错」后 `correct=false`，保存时走 `vocabApi.submitReview(correct=false)`，不写 `typo` 事件。因此 candid 的写回仍按 L1→L1（到期 +2 天），030 原有数据库预期全部保留。选择「判错」而不是「判对」，是按卡片建议保持原判错预期，没改 level 预期。`waitNextEnabled` 抄自 032 的 first-test 脚本。脚本里所有等待都带中文说明，失败截图仍在。
