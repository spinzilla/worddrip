## 目标（一两句话，用户能看懂）

录笔记开始识别后，切到别的页面、设置甚至闪卡复习，识别都在后台继续，回来时进度和已认出的词都还在；识别过程中能清楚看到每一页走到哪一步、等了多久、大概还要多久，认完一页就先显示这页的词。另外在「设置 → AI」的 API Key 旁边加上 DeepSeek 官方的创建 Key 教程链接，随机度默认改成 1。

## 要做成什么样

1. **识别任务放到页面外面**：把一次录笔记任务（待识别的页、每页状态、合并后的候选、取消）搬到一个独立的模块（例如 `app/utils/vocab/noteJob.ts`，单例 + 订阅/React hook），`InboxPanel` 只负责显示和操作它。切视图、切到设置、进闪卡/复习再回来，任务都继续，回来看到的是当前进度；只有点「取消」或「重新选择」才停。确认入库后清空。关闭应用会中断（界面上用一行小字说明）。
2. **每页详细进度**：每页一行，显示阶段——排队中 / 准备图片 / 上传中 / 等待模型回复（已等 N 秒，每秒更新）/ 完成·认出 N 个 / 失败·原因·重试。
   - 如果接口支持流式输出（OpenAI 兼容的 `stream: true`），优先用流式，等待阶段改成「模型正在写…已收到 N 字」；接口不支持流式或报错时自动退回现在的一次性请求，不能因此识别失败。流式的完整结果仍按原来的 JSON 解析。
3. **总进度**：顶部一条进度条「已完成 3 / 8 页 · 已用 1 分 20 秒 · 预计还要约 2 分钟」（按已完成页的平均用时估算，前一页没完成时显示「估算中」）；显示「正在使用模型：xxx」，并加一句小提示「识别慢的话，可以在『设置 → AI』换一个更快的看图模型」。
4. **认完一页就显示**：每页完成后它的词立刻合并进候选列表（标来自第几页），用户可以边等边核对；「确认入库」在全部页结束（完成/失败/取消）后才能点。
5. **离开页面时的提示**：识别进行中时，词库页分段条的「录笔记」段和手机底部/顶部的词库入口显示一个小转圈和「3/8」；识别全部结束而用户在别的页面时，弹一条不挡操作的提示「笔记识别完成：认出 42 个词，去确认」，点了跳回录笔记。
6. **手机切到后台**：安卓把应用切到后台时请求可能被系统暂停或断开；回到前台后，被打断的页自动重试一次，界面写明「刚才切到后台，已自动重试」。
7. 速度：同时识别的页数从 2 改成 3（`NOTE_CONCURRENCY`），其他参数不动。
8. **API Key 的教程链接**（用户 2026-11-13 加的：「不是所有人都了解 api key，在 API Key 填写的位置加上 deepseek 官方的 api key 设置教程链接」；手机、电脑的「设置 → AI」都要有）：
