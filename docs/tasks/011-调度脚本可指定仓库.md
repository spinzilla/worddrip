## 目标（一两句话，用户能看懂）

让调度脚本能给「别的仓库」干活：设了环境变量 `DISPATCH_REPO` 时，就把那个目录当成仓库（读它的任务卡、agent 名单、写它的日志和台账、在它里面提交）；没设时行为完全不变。另外让台账文件在 git 合并时自动保留两边的新行，为以后并行跑做准备。用户 2026-11-05 同意把派活范围扩到 D:\agent-board。

## 允许改动的路径

- `scripts/dispatch.mjs`
- `.gitattributes`
- `docs/dispatch.md`

## 要做的

1. `scripts/dispatch.mjs`：
   - `REPO`：若 `process.env.DISPATCH_REPO` 非空，用 `path.resolve(它)`；否则保持现在的「脚本所在仓库」。
   - 指定了 `DISPATCH_REPO` 时先检查：该目录下有 `.git`（目录或文件都算——git worktree 里 `.git` 是文件）且有 `docs/tasks/`；不满足 → 打印中文错误「DISPATCH_REPO 指向的不是可用的仓库：…」，退出码 1，什么都不做。
   - DSH 的 patch 路径改用 `path.resolve(REPO, a.patch)`（这样 agents.json 里可以写绝对路径，如 `D:/english-studio/scripts/dsh/k3.patch.yml`；原来的相对路径行为不变）。
   - 其余所有路径（LOG_DIR、LEDGER、agents.json、git 命令的 cwd、执行者的工作目录）本来就基于 REPO，确认全部跟着变；如有写死 english-studio 的地方一并改成基于 REPO。
   - 计划输出（含 `--dry-run`）第一行打印「仓库：<REPO>」。
2. 新建 `.gitattributes`，内容一行：`docs/ledger.md merge=union`（git 自带的「合并时两边新行都保留」，以后并行跑各自追加台账不会冲突）。
3. `docs/dispatch.md`：加一小节「给别的仓库派活」：`DISPATCH_REPO` 的作用；对方仓库需要的东西（`docs/tasks/`、`scripts/agents.json`、`docs/ledger.md`、`AGENTS.md`）；agent-board 的入口脚本会自动设置它；台账 union 合并的说明。

## 验收标准（验收者照着复跑）

所有会真正跑流程的测试都在**临时仓库**里做，不在 D:\english-studio 本身跑：

1. `node --check scripts/dispatch.mjs` 通过；不设 `DISPATCH_REPO` 时 `node scripts/dispatch.mjs 010 --dry-run` 正常，第一行是「仓库：D:\english-studio」。

   `DISPATCH_REPO=D:\tmp\es-repo-test DISPATCH_FAKE_AGENT=1 DISPATCH_FAKE_SECONDS=2 node D:\english-studio\scripts\dispatch.mjs 099`
   → 结果「通过」；进度文件、日志在 `D:\tmp\es-repo-test\.dispatch\`；临时仓库多了一次提交、台账多一行；**D:\english-studio 的 `git status` 和 `.dispatch/` 没有任何变化**（跑之前记下 english-studio `.dispatch/progress.json` 的修改时间，跑后比较）。
3. `DISPATCH_REPO=D:\tmp\不存在 node scripts/dispatch.mjs 099 --dry-run` → 中文错误、退出码 1。
4. union 合并：在临时仓库里（复制本仓库的 `.gitattributes` 进去并提交）开两个分支，各在 `docs/ledger.md` 末尾追加不同的一行并提交，`git merge` 两个分支无冲突且两行都在。
5. 真仓库 `git status` 只有允许路径内的文件（本卡除外）；验收后删掉 `D:\tmp\es-repo-test\`。
