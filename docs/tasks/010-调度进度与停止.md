## 目标（一两句话，用户能看懂）

让调度脚本一边跑一边把「跑到哪一步、谁在干、日志在哪」写进 `.dispatch/progress.json`，给 agent-board 看板显示进度；并支持「停止」：看板放一个 `.dispatch/stop` 文件，脚本就结束正在跑的 agent、把这张卡标成卡住、停下整批。另加一个「假执行者」开关，方便在仓库副本里测试流程而不真的调用 AI。

## 允许改动的路径

- `scripts/dispatch.mjs`
- `docs/dispatch.md`

## 要做的

1. **进度文件** `.dispatch/progress.json`（`.dispatch/` 已在 .gitignore）。每次内容变化时整份重写：先写 `progress.json.tmp` 再 `renameSync` 覆盖，避免看板读到半截文件。格式照抄（字段名不要改）：

   ```json
   {
     "version": 1,
     "pid": 1234,
     "ids": ["009", "011"],
     "startedAt": "2026-11-04T13:30:00.000Z",
     "updatedAt": "2026-11-04T13:31:05.000Z",
     "current": { "id": "009", "phase": "impl", "agent": "dsh-k3", "round": 1, "phaseStartedAt": "…", "log": ".dispatch/009-…-r1-impl.log" },
     "phases": [ { "id": "009", "phase": "precheck", "agent": "", "round": 1, "startedAt": "…", "endedAt": "…" } ],
     "results": [ { "id": "009", "result": "通过", "why": "" } ],
     "done": false,
     "stopped": false
   }
   ```
   - `phase` 只用这几个值：`precheck`（前置检查）、`impl`（实现，返工时 round=2）、`scope`（越界检查）、`review`（验收，返工后再验收 round=2）、`commit`（台账 + 本地提交）。
   - `current.log` 是相对仓库根的路径，只在 impl/review 阶段有值，其余为 `""`；`agent` 同理。
   - 进入新阶段时：把上一阶段写进 `phases`（补 `endedAt`），再更新 `current`。一张卡结束时 `current` 置 `null`，`results` 追加一条（`result` 用脚本现有的「通过 / 跳过 / 卡住 / 实现失败 / 验收失败 / 人工停止」等文字，`why` 为原因）。整批结束 `done: true`。
   - `--dry-run` 不写进度文件。脚本启动时若已有 `progress.json`，直接覆盖。
2. **停止**：
   - 启动时先删掉旧的 `.dispatch/stop`（如果有）。
   - agent 子进程运行期间每秒检查一次 `.dispatch/stop`；出现就用已有的 `taskkill /PID … /T /F` 结束子进程。各阶段之间也检查一次。
   - 被停止的卡：状态改为 `卡住 @调度脚本 <日期>（人工停止，改动留在工作区）`，`results` 记 `{"result":"人工停止"}`，`stopped: true`、`done: true`，不跑后面的卡，删掉 stop 文件，退出码 1。不做回滚，不提交。
3. **假执行者**（只给测试用）：环境变量 `DISPATCH_FAKE_AGENT=1` 时，`runAgent` 不调用任何真实程序，而是：等待 `DISPATCH_FAKE_SECONDS`（默认 3）秒（期间照样每秒检查 stop），日志文件写几行「[假执行者] …」；实现阶段在卡片「结束报告」里写一行「- 改了什么：（假执行者，未改代码）」；验收阶段在卡片末尾追加「验收结论：通过」。返回退出码 0。**不改任何代码文件**，这样越界检查和提交都能正常走完（只提交卡片和台账）。
4. `docs/dispatch.md` 加一小节：进度文件的作用和格式要点、怎么停止（创建 `.dispatch/stop`）、假执行者开关只用于在仓库副本里测试。
