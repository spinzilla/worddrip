## 目标（一两句话，用户能看懂）

在现有客户端增加「词库」入口：选择学术升级库和复习库 Markdown，先看条数和问题，再确认导入。数据保存在本应用的独立词库数据库，重启后仍能看到导入统计。

## 从哪看起

- `app/utils/vocab/parse.ts`、`types.ts`：007 的纯解析函数，直接复用，不在 Rust 重写一套 Markdown 解析器。章节名不匹配目前会静默返回空结果，必须在本次导入边界明确拒绝。
- `app/src-tauri/src/vocab/schema.rs`：008 的 5 张表、外键、版本迁移；`import_run` 已有来源、哈希、计数和警告字段。数据库位置由 `db_path()` 决定。
- `app/src-tauri/src/lib.rs`：注册 Tauri command（前端调用 Rust 的入口）；当前没有词库 command。
- `app/App.tsx`、`components/Shell.tsx`、`types.ts`：现有页面和导航；保留精听及现有 FSRS 卡片入口。
- `docs/vocab-data-model.md` 第 5.4 节是存储拍板：rusqlite + command + 前端 vocabApi，覆盖早期草案中 SQL 插件的说法。

## 要做的

1. 新增词库页面及最小导入区。用已有文件选择能力读取两份 UTF-8 Markdown，展示文件名、有效记录数、警告的行号和原因；取消选择不报错、不写库。文件内容按普通文本渲染。
2. 预览采用 007 的结果；缺目标章节/表头、任一主表为空、列数错误或未知状态时阻止提交并说明原因。重复词警告允许导入；例句无法拆分时保留原文并显示警告。旧解析器的既定规则可保持不变，在导入适配层补检查。
3. 确认只提交当前预览的内容快照；重新选择文件使旧预览失效。按钮防重复点击，离开页面清理异步结果，旧请求不能覆盖新选择。预览、取消不得创建或修改数据库。
4. Rust 在事务前校验输入字段、ID 唯一性、例句引用、状态与 level、日期格式；不能仅信前端。两份文件及各自的 import_run 在同一个事务提交，任一步失败全部回滚，错误可读。
5. 首版导入规则固定：相同 ID 且业务内容一致则跳过；相同 ID 但内容不同则拒绝整批并报告冲突，不覆盖已有记录；新 ID 追加。业务内容比较不含行号、顺序和导入时间；跳过项保留数据库原值。绝不因来源缺行删除旧记录。同词不同 ID 必须全部保留；同内容第二次导入词条与例句数量不变。
6. 保存完整 raw、line、顺序、备注、例句和来源文件的内容 SHA-256；不截断备注。新增行 ord 在对应表末尾按本批原顺序追加。结果区显示新增、跳过、失败原因及库内总数；可通过只读统计 command 在重启后查看总数。
7. 前端统一通过 `app/utils/vocab/api.ts` 的 vocabApi 调用 command，组件不直接写 SQL。沿用 rusqlite，不新增依赖或改变 schema v1；新库父目录按需创建，仅在确认导入时写入。
