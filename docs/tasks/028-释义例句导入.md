## 目标（一两句话，用户能看懂）

把各期词汇存档里的词性、英英释义、中文对照和例句导入软件，让查词页和出题能用上，而不是只有一段中文备注。

## 从哪看起

- `docs/vocab-data-model.md` 第 77、144–145、165–166 行：旧网站怎么从期文件和 EAGP 词表补释义，以及已知的匹配缺陷。
- 原料（只读副本）：`D:\tmp\es-import\释义原料\词汇\*.md`（各期存档），`D:\tmp\es-import\释义原料\EAGP-词表-文本.md`。期文件格式示例见其中的 `20261020.md`「词单分析」一节，如 `1. **adjust** v. — to change slightly to fit new conditions（调整、适应；adjust to）；AWL-5`。
- `app/src-tauri/src/vocab/schema.rs`（当前 v4）、`import.rs`、`query.rs`。

## 要做的

1. 数据库升到 v5，新增释义表：词条 ID、词性、英英释义、中文对照、例句（可多条，每条记来源文件和是否 AI 草稿 `(AI)`）。
2. 解析器兼容期文件的三种写法：「编号 + 粗体词 + 词性 — 正文」「粗体词 — 正文」「英文词 — 正文」。英文释义和括号里的中文分开存；正文里的英文例句（斜体或引号句）存成例句。
3. 匹配到词条：先按「同一期号 + 词目小写」，再按词目小写；同词多个 ID 时只挂同期那个，匹配不到的列进报告，不猜。EAGP 词表只给还没有释义的词兜底。
4. 导入面板加「导入释义」：选择期文件（可多选）和 EAGP 词表，先预览再确认；显示匹配、未匹配、跳过数量。重复导入不产生重复数据。
5. 只新增释义表数据，不改复习状态、到期日和备注。

### 三、问题清单（按严重程度排序，每条都有复现步骤）

1. **【中，导致不通过】单日期号的「期号」补了零，9.1 期文件的同期优先匹配实际不生效。** `definition.rs:122` 用 `format!("{month}.{day:02}")`，`20260901.md` 得到 `"9.01"`；而复习库里的期号是 `"9.1"`（我直查本次隔离库：`review_word.issue` 有 26 行是 `9.1`，9.1 期的 14 条释义入库后挂的正是这些行）。`match_candidate` 里 `&item.issue == issue` 永远不等，于是一律退回「全局唯一」判定。当前 14 个词恰好都只有一个 ID，所以数字上没出错；但只要某个词同时出现在 9.1 和别的期（库里已有 6 组同词多 ID），解析 9.1 期时就会报「同词有多个词条 ID，且没有唯一同期项」并**跳过这条释义**，而不是按卡要求挂到同期那条。复现：`cd app/src-tauri && cargo test --lib`，临时给 `definition.rs` 加 `assert_eq!(issue_from_file("20260901.md").as_deref(), Some("9.1"));`，实际得到 `Some("9.01")`（我已删掉该临时断言并还原文件，sha256 一致）。修法很小：日期不补零，或者两边统一归一化。
2. **【低】正文开头的裸词性没归到词性列，反而当成英英释义。** 复现：真实原料 `20260825.md:12 hook — v./n. 勾`，解析结果 `pos=""`、`english="v./n."`、`chinese="勾"`；打开应用里 hook 的详情会显示「未标词性」和英英释义 `v./n.`。真实原料写入的 381 条里 122 条词性为空，其中 8.25（14/14）、8.26（29/29）、8.29（14/14）、9.01（14/14）是这种「词 — 词性 中文」原始清单，71 条把词性塞进了英文释义列。卡里的三种写法没明说词性可以出现在破折号后面，所以不单独判失败，但建议顺手把行首裸词性（`v./n.`、`adj.` 等）抽到词性列。
