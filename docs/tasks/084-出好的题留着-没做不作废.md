## 要做成什么样

1. **出好的题存起来**：一轮题准备好后，把每道题按词存一份「待做题」缓存。
   - 缓存只在本机：放 localStorage 或应用数据目录都行，选一种并在代码注释里写原因。
   - 不进同步、不进 083 的设置快照（`settingsBackupLogic.ts` 的 `SETTINGS_KEYS`）、不进整库搬家。丢了就重新出题，不算丢数据。
2. **下次出题先用缓存**：同一个词下次再出题时，如果缓存里有它的待做题且仍然有效，就直接用，不再请求模型。缓存里没有的词才照旧出题。
   - 有效的条件：
     - 题目存了不超过 7 天；
     - 出题时用到的词条内容没变（词目、词性、释义、用的那句例句）。可以用这些内容算一个指纹，和题目一起存，对不上就作废。
3. **什么时候算用掉**：
   - 这道题作答并判完分，就从缓存删掉。
   - 点了「这题出错了」的题也删掉。
   - 一轮做了一半退出：做过的删掉，没做的留着。
4. **退出时正在准备的题也别丢**：退出后模型才返回的结果，界面不显示，但照样写进缓存，下次能用。
5. 到期复习和新词首考两个入口都要做；两个入口的同一个词共用一份缓存还是分开，自己定，写进结束报告。
6. 准备题目的弹层里，如果全部来自缓存，可以不显示「正在准备题目」，直接进第一题。

#### 问题清单（按严重程度）

1. **提示（本卡）** 缓存命中会占掉限额、把位置更靠前的未缓存词挤掉，并把「还剩几个」算少。复现：临时脚本里先只给第三个词出题缓存，再用 `limit: 2` 出 `[alpha, bravo, charlie]`，得到 `[alpha, charlie]`、`remaining = 0`（按原逻辑应是 `[alpha, bravo]`、还剩 1 个）；正常使用里缓存题大多在最前面，所以平时看不出来，只有在两次出题之间插入了更早到期/更早期号的词时才碰上。影响：某一轮会先给旧缓存的词，结果页的「还有 N 个没轮到」可能说少。建议：先按队列顺序取前 `limit` 个词，再决定哪些用缓存、哪些现出。
2. **提示（本卡）** 模型配置变化不会让缓存失效。用户先没配模型出过一轮（只有英文释义的兜底题），之后配好模型再点出题，7 天内仍拿到那批旧释义题且不再请求模型，容易被误会成「模型没生效」。卡片只要求「7 天 + 词条内容」两条有效性条件，所以不算不达标；建议把「出题时有没有模型/是否混入改写造句」也算进有效性判断。
3. **提示（本卡）** 指纹只含词目、词性、英文释义和例句，不含中文释义；只改中文释义时，旧题里的中文提示会沿用 7 天。建议把 `chinese` 也放进 `recallWordFingerprint`。
