## 目标（一两句话，用户能看懂）

设置里加「整库搬家」：在电脑上点「导出整个词库」得到一个文件，传到手机上点「导入整个词库」，手机上就有和电脑一模一样的词、复习进度、笔记和随手记。反过来手机导出、电脑导入也行。

## 从哪看起

- 词库数据在 Rust 的 SQLite 里，数据目录见 `app/src-tauri/src/paths.rs` 的 `app_data_dir()`，打开数据库和建表/迁移在 `app/src-tauri/src/vocab/`（`mod.rs`、`schema.rs`、`commands.rs`）。随手记在 `vocab/quicknote.rs`。
- 前端文件选择和读写：`app/utils/vocab/api.ts`（已经在用 `@tauri-apps/plugin-dialog` 的 `open`/`save` 和 `@tauri-apps/plugin-fs`）。
- **安卓上文件选择返回的是 `content://` 地址，不是普通路径**：Rust 里的 `std::fs` 打不开它。读写要走 `plugin-fs`（它在安卓上能读写 `content://`），或者把字节传给 Rust。另外安卓的文件选择按 MIME 类型过滤，按扩展名过滤可能不起作用，选文件时不要因为过滤导致选不到。能用的权限在 `app/src-tauri/capabilities/`。
- 设置页：`app/components/Settings.tsx`（电脑上的 `BackupRow` 是上游的备份，和本卡无关，不要动它也不要复用它的格式）。059 改过手机设置分页，新分组两边都要显示。
- 059 让手机词库空着时不显示「去导入」，本卡把那段空状态文案改成指向「设置 → 整库搬家」。

## 要做成什么样

1. **导出**：用 SQLite 的在线备份（`rusqlite` 的 backup API 或 `VACUUM INTO`）先生成一份完整、一致的副本，再让用户选保存位置。默认文件名形如 `词滴词库-20261112-1830.wdlib`（扩展名你定，报告里写清）。
2. **导入**：选文件 → 先检查：是不是 SQLite、是不是我们的词库（必须有的表都在）、版本不比本机新（比本机旧就照常跑迁移）。检查不过就报清楚原因，本机数据不动。
3. 检查通过后**先给用户看摘要再确认**：文件里有多少词、今天到期多少、笔记几条、随手记几条、导出时间；明确写「会覆盖本机现在的词库，本机词库会先自动备份」。
4. 确认后：先把本机当前词库备份到数据目录里（带时间戳，最多保留最近 3 份），再替换，然后重新打开数据库、刷新界面。替换要安全：先写临时文件，成功后再换名；换的过程中失败，本机词库必须保持原样。
5. 本机词库正在被别的地方用着（比如复习进行中）时，先结束或提示，不要换到一半。
6. **随手记「导出 随手记.md」在安卓上也要能保存**（059 验收时发现，`app/components/vocab/QuickNotesPanel.tsx` 用 `save` + `writeTextFile`，安卓上 `save` 返回的是 `content://`）：和整库导出走同一条能写 `content://` 的路子；电脑版行为不变。
7. 词库之外存在 localStorage 里的东西（设置、界面偏好等）不搬，报告里列一下有哪些、为什么不搬。
