## 目标（一两句话，用户能看懂）

让应用自己记住「哪些数据改过」，能把改动推到同步服务、把别的设备的改动拉回来合进本机词库：后改的为准、复习记录只增不删、删除会传过去不会复活，两台设备第一次同步不出重复。界面（设置里的同步栏）是下一张卡。

## 要做成什么样

1. **同步身份**：
   - TEXT 主键表用主键本身；复合主键表用各列按固定顺序拼成的字符串（分隔符选一个不会出现在值里的，写清楚）。
   - 自增整数主键的 5 张表加一列 `sync_uid TEXT UNIQUE`：新行用 UUID；**已有行回填用确定性算法**：`legacy:` + 表名 + 本机整数 id + 这行创建时就定下、之后不改的字段（如创建时间、正文前若干字）的哈希。同一份数据库复制出的两台设备算出来一样，两台设备复制之后各自新加、恰好撞号的行算出来不一样。回填规则逐表写进结束报告。
2. **改动记录**：新表 `sync_change(tbl, sid, updated_at INTEGER 毫秒, deleted INTEGER, dirty INTEGER, PRIMARY KEY(tbl, sid))`；对白名单里每张表建 INSERT/UPDATE/DELETE 触发器，任何代码路径改了数据都会记一笔（`dirty=1`、`updated_at=当前毫秒`、删除记 `deleted=1`）。应用远端改动时用一个开关让触发器不记（例如 `sync_meta` 里的 `applying` 标志 + 触发器 `WHEN` 条件）。
3. **设备号**存在 `vocab.db` **之外**（数据目录下单独一个文件），这样整库复制不会把设备号也复制过去。`sync_meta` 存每个服务器地址的 `cursor` 和上次同步时间。
4. **推送**：取 `dirty=1` 的改动，读出整行转成 JSON（列名 → 值；自增 id 列不放进 data，用 sync_uid 当身份），分批 ≤ 500 条推送；服务端返回成功后把这批 `dirty` 清掉（推送期间这些行又被改了的不能清）。
5. **拉取并合并**：按 cursor 分页拉；每条：本机同一 `(tbl,sid)` 有 `dirty=1` 且本机 `updated_at` 更新 → 跳过（等下次推上去）；否则按 data 写入（整数主键表按 `sync_uid` 找本机行，没有就新插一行由本机分配整数 id；data 里本机没有的列忽略、本机有 data 没有的列用默认值），`deleted=true` 就删本机行；然后把 `sync_change` 设为远端的 `updated_at`、`dirty=0`。一页一个事务；有外键的表（如 `coach_top_progress` → `error_top`）注意顺序或延迟外键检查。
6. **首次同步与整库搬家**：
   - 开启同步后第一次：把所有白名单表的现有行都记成 `dirty=1`，`updated_at` 用这行已有的修改时间（有 `updated_at`/`imported_at` 列就解析，没有就 0），全部推一次再拉；服务端按后改的为准，两边内容相同就不会出现重复。
   - 060 的「导入整个词库」成功后：cursor 归零，所有行重新记成 `dirty=1`（同上规则）。
7. **对外接口**：Rust 命令（`sync_collect`、`sync_ack`、`sync_apply`、`sync_status`、`sync_reset` 之类，名字你定）+ 前端 `app/utils/sync/`：
   - `syncNow({ baseUrl, appKey, spaceId, spaceSecret })`：先推后拉，返回「推了几条、拉了几条、跳过几条、耗时、错误」；同一时间只允许一次同步。
   - `createSpace({ baseUrl, appKey })`、`deleteSpace(...)`、`spaceInfo(...)`，对应 070 协议的 `/spaces`、`DELETE /space`、`GET /space`。
   - **同步码**：`encodeSyncCode(spaceId, spaceSecret)` / `decodeSyncCode(code)`：拼成便于抄写复制的一串（只用大写字母和数字，按 4 位一组用短横线分开，带一位校验码，抄错能发现），解码时容忍大小写和多余空格。
   - **内置服务器**：默认地址 `https://vocab.uestceee.art/sync-api` 写成常量；应用口令在构建时从环境变量 `VITE_SYNC_APP_KEY` 读进来（本机放 `app/.env.local`，已被 `.gitignore` 的 `.env.*` 忽略），仓库里不出现真实值；没配置时同步功能显示「这个版本没有内置同步」并不可用。测试用测试口令。
   - 错误给中文原因：网络错误、401（同步码不对或空间已删除）、403 名额已满、413、429 太频繁、507 同步空间已满、5xx。应用口令、空间密钥、同步码只在内存和本机设置里，不写日志、不进错误信息。
8. 不同步：`import_run`、听力单词卡（不在 vocab.db 的数据）、设置、AI 密钥。

## 验收标准（验收者照着复跑）

1. 不坏老功能：`cd app && npx --no-install tsc --noEmit`、`npm run build` 退出码 0；`cd app/src-tauri && cargo test vocab` 退出码 0；`node dev/e2e/smoke.mjs`、`node dev/e2e/library-transfer.mjs`、`node dev/fixtures/vocab/review-session/e2e.mjs`、`node dev/fixtures/quicknote/e2e.mjs` 退出码 0。
2. Rust 单测覆盖：触发器在增/改/删时都记账、应用远端时不记账；整数主键表回填 sync_uid 的确定性（同一份库两次回填一样、复制后各自新增撞号的行不一样）；合并规则（本机脏且更新 → 跳过、远端更新 → 覆盖、删除传播且旧修改不能复活、只增不删表）；列不一致时不报错；外键表顺序；导入整库后同步状态被重置。
3. 联调（本机起 `server/sync` 服务 + 两个隔离数据目录 A、B，验收者自己写脚本，可以直接调前端接口或 Rust 命令）：
   - A `createSpace` 得到空间，生成同步码；B 用 `decodeSyncCode` 解出同一空间（再故意改错一位，解码报「同步码有误」）；另建一个空间 C 写点数据，确认 A、B 拉不到 C 的数据；
   - B 用 A 的整库导出导入（模拟用户现在的情况）→ A、B 各同步一次 → 两边每张表行数和改前一样（无重复）；
   - A 加一个词、复习一次、写一条笔记和一条随手记 → A 同步 → B 同步 → B 都有；
   - A、B 都改同一个词的复习备注，B 后改 → 两边各同步两轮 → 两边都是 B 的内容；
   - A、B 各自复习同一个词（各产生复习记录）→ 同步后两边复习记录是两边的并集；
   - A 删一条笔记 → 同步 → B 也删了；B 之后不会把它同步回来；
   - 同步中途断开服务（停掉 uvicorn）→ 报中文网络错误，本机数据不坏，恢复服务后再同步能补上。
   每步写出关键表的行数或查到的内容作为证据。
4. 安卓编译：`node app/dev/build-android.mjs` 退出码 0（同步代码在安卓上也能编过）。
5. 结束报告写清：每张表的同步身份规则、sync_uid 回填规则、首次同步时 updated_at 怎么定、数据库版本号从几升到几。
