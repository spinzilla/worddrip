## 目标（一两句话，用户能看懂）

软件能记住一次产出题复习的结果：答对升一级，答错回 L1，并算好下次到期日。本卡只做后端和规则，不做界面。

## 要做的

1. 数据库升到 v3，新增表 `review_log`：词条 ID、复习日、题型、是否答对、前后状态、前后到期日、创建时间。v2 升级后原数据不变。
2. 写一个纯函数算下一状态，今天由参数传入，规则如下：
   - 题型：`recall`（回忆填空）、`rewrite`（改写）、`sentence`（造句）是产出题；`choice`（选择题）只记日志，永不改状态。
   - 🌱待考察：答对 → ✅已掌握，到期日清空，备注追加「；YYYY-MM-DD 首考过」；答错 → L1。
   - L1 答对 → L2（+4 天）；L2 答对 → L3（+8 天）；L3 答对 → L4（+16 天）；L4 答对 → ✅已掌握，到期日清空。
   - 任何 L 级答错 → L1（+2 天）。
   - 同一词同一自然日，只有第一次产出题结果改状态，之后只记日志，答错也不再降级。
   - ✅已掌握、🧊冷库、已软删除、不存在的 ID：返回明确错误，不写任何数据。
3. 新增命令 `vocab_review_submit`（词条 ID、题型、是否答对），在一个事务里更新 `review_word` 的 status、level、due、note、updated_at 并写日志。今天取本机自然日，不用 UTC。
4. `api.ts`、`types.ts` 加上调用和类型。

### 问题清单（按严重程度）

1. **低｜同日第二次产出题遇到「第一次答对后词条已变 ✅已掌握」会报错，而不是只记日志。** 复现：v3 库里放一个 🌱待考察 词 → 当天 `recall` 答对（变 ✅已掌握，日志 1 条）→ 同日再提交 `sentence` 答对 → 返回「词条已掌握，不能复习」，日志仍 1 条、词条不变。代码在 `review.rs:88-96`：status 校验在同日 `already_reviewed` 判断之前；现有测试没覆盖这个组合。影响有限（到期队列会排除已掌握词，单窗口正常流程很难二次提交），但 023 的「同日重复做的词显示今天已计入，不再升级」需要这条路径能成功，建议 023 开工前明确该场景以哪条规则为准。
2. **低｜v2 库升级后只读浏览可能先报「版本不兼容」。** `query::browse_at` 只读且要求 `user_version == 3`（`query.rs:29`）；v2 用户换新版本后，如果「浏览」请求先于任何走 `schema::open` 的命令（`vocab_stats` 等）完成，会看到「词库数据库版本 2 与本应用支持的版本 3 不兼容」。切到导入/导出触发 stats 迁移、再切回浏览即恢复。018 从 v1 升 v2 时就是同样的模式，不是本卡引入，但本卡会让现有 v2 用户首次遇到。复现：造一个 user_version=2 的库 → 调 `vocab_browse` → 报不兼容；调 `vocab_stats` 后再 `vocab_browse` → 正常。建议后续卡在启动时主动迁移。
3. **提示（不阻塞）｜导出重建行未处理备注里的半角 `|`。** `export.rs:38-53` 在被写回的行上按当前字段重拼六列；备注若含 `|` 会变成七列。正常导入解析要求复习库恰好 6 列（`parse.ts:136`），这种备注进不了库，只有绕过解析直接写库才会出现。
